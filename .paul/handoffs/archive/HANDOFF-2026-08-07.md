## Traps That Have Already Bitten (do not repeat)

1. **Never read an exit code through a pipe.** `cmd | tail` returns *tail's* status. This masked an
   ESLint crash in 02-01 and a hook failure in 01-01 — twice producing the wrong conclusion.
2. **ESLint is pinned to 9.** `eslint-config-next@16`'s bundled plugins (react, import, jsx-a11y,
   react-hooks) all cap at `^9` and **crash ESLint 10** at rule-load time. Do not upgrade until
   they declare 10 support.
3. **Next.js 16 rewrites `AGENTS.md`.** It injects an H1 `nextjs-agent-rules` block on every
   `next dev`, via `node_modules/next/dist/server/lib/generate-agent-files.js`. Verified: deleting
   it and running the dev server brings it back. Commit it; never fight it. `MD025` is disabled in
   `.markdownlint-cli2.jsonc` because of this.
4. **Never run `create-next-app` in this directory.** It would overwrite `README.md`, `.gitignore`,
   `eslint.config.mjs`, and the `package.json` scripts.
5. **Tailwind 4 is CSS-first.** There is no `tailwind.config.js`; theme customisation goes in
   `app/globals.css` via `@theme`.
6. **Read installed package exports before writing config.** Both version assumptions in 02-01
   (the `eslint-config-next` flat entry point, and Tailwind's major-version config style) differed
   from what a reasonable guess would have produced.
7. **The phase-completion heuristic gives false positives.** PAUL detects "last plan in phase" by
   comparing PLAN/SUMMARY file counts, which match at 1=1 whenever only one plan file exists yet.
   `.paul/ROADMAP.md` is the authority — it declares 6 plans for Phase 2. The transition has
   correctly been withheld twice for this reason.
8. **Verify, don't assume — it has repeatedly paid off.** CI was proven to *fail* (not just pass)
   before being trusted; a "green" ESLint run was hiding a crash; and a settings API returned
   HTTP 200 while silently ignoring the write.
