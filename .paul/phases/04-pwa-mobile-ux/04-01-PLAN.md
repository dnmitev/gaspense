<objective>
## Goal

Make Gaspense installable on a phone home screen and functional when the network drops —
a complete web app manifest, real raster icons, and a hand-written service worker whose
caching policy is deliberately narrow: static assets only, never authenticated HTML and
never `/api`.

## Purpose

Phase 4's goal is "app installs on a phone home screen and adding an expense takes
seconds". This plan delivers the first half. It is the only third of Phase 4 with no
blockers — it touches no schema and no external service, unlike 04-03's attachments.

The narrow cache policy is the substance of this plan, not a detail. A service worker is
a proxy that outlives a page: cache one authenticated HTML response and the app will serve
one account's expense list to a later request, and keep serving a signed-in page after
sign-out. The caching rule is therefore a security boundary, and this plan proves it by
going offline and checking what comes back — not by asserting the rule in a comment.

## Output

- `app/manifest.ts` — the web app manifest, served at `/manifest.webmanifest`
- `public/icon.svg` plus generated PNG icons, and `scripts/generate-icons.ts` to regenerate them
- `public/sw.js` — the service worker; `public/offline.html` — its navigation fallback
- `app/service-worker-registration.tsx` — the registration client component, rendering nothing
- Unit tests over the cache policy and the icons' real pixel dimensions
- `tests/e2e/pwa.spec.ts` — installability, registration, and the offline behaviour proof
- Updated `CLAUDE.md`, `AGENTS.md`, `docs/ARCHITECTURE.md`
</objective>

<acceptance_criteria>

## AC-1: The manifest is served, complete, and reachable without a session

```gherkin
Given a browser with no session cookie
When it requests /manifest.webmanifest
Then the response is 200 with a JSON body
And it declares name, short_name, start_url, display "standalone", theme_color,
    background_color, and icons at 192x192 and 512x512
And at least one icon declares purpose "maskable"
```

## AC-2: The icons are real rasters at the sizes the manifest claims

```gherkin
Given the PNG files committed under public/
When their IHDR headers are read from disk
Then each file's actual pixel dimensions equal the size the manifest declares for it
And each file is a valid PNG rather than a renamed placeholder
```

## AC-3: The service worker registers and takes control

```gherkin
Given a page load in the running app
When the registration component runs
Then navigator.serviceWorker.ready resolves
And the resolved registration has an active worker controlling the page
```

## AC-4: Authenticated HTML is never served from the cache

```gherkin
Given a signed-in user who has loaded the dashboard at /
When the browser goes offline and navigates to / again
Then the offline fallback page is served
And the response body contains none of that user's data — no licence plate, no euro total
```

## AC-5: Static assets are served from the cache when offline

```gherkin
Given a page load that has populated the static cache
When the browser goes offline and requests /icons/icon-192.png
Then the request succeeds from the service worker cache rather than failing
```

  <files>app/manifest.ts, app/layout.tsx, public/icon.svg, public/icons/icon-192.png, public/icons/icon-512.png, public/icons/icon-maskable-512.png, public/apple-touch-icon.png, scripts/generate-icons.ts, package.json</files>
  <action>
    Create `public/` — it does not exist yet.

    **The icon source is one hand-authored SVG** at `public/icon.svg`. Keep it simple and
    legible at 48px: a fuel-drop or gauge mark on a solid background, in the neutral palette
    the app already uses. No text — text is unreadable at icon size and locks the icon to
    one language.

    **Rasterise with the Chromium that Playwright already installs**, via
    `scripts/generate-icons.ts` run under `tsx`, wired as `npm run icons:generate`. This adds
    no dependency: `@playwright/test` is already a devDependency and its browser is already
    installed in CI. Do NOT add sharp, resvg, or any image library for four files.

    The script loads the SVG at each target size and screenshots it to PNG. Produce:
    - `public/icons/icon-192.png` — 192x192, purpose "any"
    - `public/icons/icon-512.png` — 512x512, purpose "any"
    - `public/icons/icon-maskable-512.png` — 512x512, purpose "maskable", drawn with the
      artwork inside the inner 80% safe zone so Android's mask cannot clip it
    - `public/apple-touch-icon.png` — 180x180. iOS ignores manifest icons entirely; without
      this an installed icon on iPhone is a screenshot of the page.

    **Commit the PNGs.** They are build inputs served statically by Vercel, which will not
    run the generator — this is a deliberate, narrow exception to "do not commit generated
    output", and the tracked script is what keeps them reproducible when the SVG changes.

    **`app/manifest.ts`** returns a typed `MetadataRoute.Manifest`. Use Next's file
    convention rather than a static `public/manifest.json` so the type checker catches a
    malformed manifest at build time. Set `start_url: "/"`, `display: "standalone"`,
    `background_color` and `theme_color` matching the app's light background.

    **`app/layout.tsx`**: add `themeColor` (light and dark variants) to the existing
    `viewport` export, and `appleWebApp` plus `icons.apple` to the existing `metadata`
    export. Next emits the manifest link tag itself from the file convention — do not
    hand-write a `<link rel="manifest">`.

    Avoid: declaring an icon size the file does not actually have. A manifest that claims
    512x512 over a 192px file passes every review and fails installability silently.
  </action>
  <verify>`npm run build` succeeds; `npm start` then `curl -s localhost:3000/manifest.webmanifest` returns the complete JSON; `npm test` shows the new icon-dimension test green</verify>
  <done>AC-1 and AC-2 satisfied: manifest complete and served without auth; every PNG's IHDR matches its declared size</done>

<task type="auto">
  <name>Task 2: The service worker, its cache policy, and its registration</name>
  <files>public/sw.js, public/offline.html, app/service-worker-registration.tsx, app/layout.tsx, eslint.config.mjs</files>
  <action>
    **`public/sw.js` — an ES module service worker**, registered with `{ type: "module" }`.
    Module registration is what lets Vitest import the file and unit-test the policy directly,
    so the browser and the test run the same source with no build step and no duplicated rule.

    Export two pure predicates and test them, then wire the listeners at the bottom of the
    same file:

    - `shouldCache(request)` — true only for same-origin GET requests for static assets:
      `/_next/static/*`, `/icons/*`, `/icon.svg`, `/apple-touch-icon.png`,
      `/manifest.webmanifest`, `/offline.html`.
    - `isNavigation(request)` — `request.mode === "navigate"`.

    **The policy, stated as the rule it is:**
    - **Never cache HTML.** Every page in this app is behind a session and renders one
      user's rows. A cached navigation response would survive sign-out and outlive the
      session that authorised it.
    - **Never cache `/api/*`**, which is where auth lives.
    - **Never cache a non-GET request**, and never cache an opaque cross-origin response.
    - Static assets: cache-first, falling back to network and populating the cache.
    - Navigations: network-only, falling back to `/offline.html` from the precache when the
      network fails. Do not fall back to a cached page — there are none, by the rule above.

    `install` precaches `/offline.html` and the icons, then `skipWaiting()`. `activate`
    deletes every cache whose name is not the current `CACHE_VERSION`, then `clients.claim()`
    so the first load is controlled rather than the second. `CACHE_VERSION` is a constant
    bumped by hand; note in a comment that it must be bumped when the precache list changes.

    **`public/offline.html`** — a static page, no user data, no auth, no fetch. States that
    the device is offline and that recorded data is safe. It must be renderable with zero
    JavaScript and zero network.

    **`app/service-worker-registration.tsx`** — `"use client"`, a `useEffect` calling
    `navigator.serviceWorker.register("/sw.js", { type: "module" })` guarded on the API
    existing, returning `null`. Mount it in `app/layout.tsx`.

    ⚠️ **This is the app's first layout-level client boundary**, and STATE.md flags "the app
    ships almost no client JavaScript" as its strongest asset going into Phase 4. That is the
    price of installability and there is no server-side way to register a worker. Keep it to
    the minimum: this component renders nothing, holds no state, and imports nothing else.

    **`eslint.config.mjs`**: add an override for `public/sw.js` declaring the service-worker
    globals (`self`, `caches`, `clients`, `fetch`, `Response`) as readonly. Without it
    `npm run lint` fails on undefined globals and the gate goes red.

    Avoid: `next-pwa` or Serwist — settled at planning time. Avoid caching the navigation
    response "just for the shell"; that is exactly the bug this policy exists to prevent.
  </action>
  <verify>`npm run lint` passes with sw.js present; `npm run build && npm start`, then in the browser `navigator.serviceWorker.ready` resolves with an active worker; DevTools Application → Cache Storage shows static assets and `/offline.html` and no HTML document</verify>
  <done>AC-3 satisfied: the worker registers and controls the page. AC-4 and AC-5 are proven in Task 3</done>
</task>

    `public/sw.js` and drive them directly. Cover, as a table: a `/_next/static` GET (cache),
    an icon GET (cache), a navigation to `/` (never), a navigation to `/cars/abc/expenses`

    cross-origin GET (never). Each false case gets its own named assertion — a single
    "returns false for bad input" test cannot say which rule broke.

    **`tests/unit/icons.test.ts`** — read each committed PNG with `node:fs`, assert the
    8-byte PNG signature, then parse width and height from the IHDR chunk (bytes 16–23,
    big-endian) and assert they equal the manifest's declared size. Import the manifest from
    `app/manifest.ts` and drive the assertions from it, so a manifest edit that outgrows the
    files fails here rather than in a store review.

    **`tests/e2e/pwa.spec.ts`** — a new file. Do not edit `tests/e2e/home.spec.ts`; it was
    rewritten in 03-03 and this plan has no business in it.

    1. Signed out, `request.get("/manifest.webmanifest")` returns 200 and the parsed body
       carries every required field, including a `maskable` icon. (AC-1)
    2. Each icon URL returns 200 with `content-type: image/png`. (AC-2)
    3. `page.evaluate(() => navigator.serviceWorker.ready.then((r) => !!r.active))` is true. (AC-3)
    4. **The load-bearing test.** Sign in with `seedUserWithSession` + `applySessionCookie`,
       seed demo data, load `/` and assert the licence plate is visible. Wait for the worker

       Assert the offline fallback's copy is visible, and assert `DEMO-0001` and the euro
       total are **absent** from the response body. Absence is the whole point: a passing
       "offline page shows" without the absence check would still pass if the worker were
       serving cached user data alongside it.
    5. Offline, `/icons/icon-192.png` still resolves 200 from the cache. (AC-5)

- **No quick-add expense flow** and no navigation restructure — that is 04-02

  Playwright Chromium; the service worker is hand-written
