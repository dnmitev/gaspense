<objective>
## Goal

Stand up the Next.js application skeleton — App Router, TypeScript, Tailwind — inside the existing
repo without disturbing the tooling, docs, or CI that Phases 0 and 1 established, and add a `build`
step to CI so a broken build is caught from the first commit of application code.

## Purpose

First plan of Phase 2 and the first application code in the project. Everything after this
(Prisma schema, NextAuth, the CRUD slices) needs a working Next.js app and a build gate that
proves it compiles. Getting the scaffold to coexist with the Phase 0 lint setup is the whole
difficulty here, so it is isolated into its own plan rather than bundled with features.

## Output

- Next.js App Router app that builds and serves one page
- `eslint-config-next` merged into the existing flat config, with Prettier still last
- `dev` and `build` scripts
- A `build` step in `.github/workflows/ci.yml`
</objective>

<task type="auto">
  <name>Task 1: Add Next.js, React, and Tailwind and create the minimal App Router app</name>
  <files>package.json, package-lock.json, tsconfig.json, next.config.ts, postcss.config.mjs, app/layout.tsx, app/page.tsx, app/globals.css</files>
  <action>
    **Do NOT run `create-next-app` in this directory.** It would overwrite `README.md`,
    `.gitignore`, `eslint.config.mjs`, and the `package.json` scripts — all Phase 0/1 artefacts
    that AC-4 protects. Install the dependencies and write the files directly instead.

    Install as runtime dependencies: `next`, `react`, `react-dom`.
    Install as devDependencies: `typescript` (already present), `@types/node`, `@types/react`,
    `@types/react-dom`, `tailwindcss`, `@tailwindcss/postcss`, `postcss`.

    Check the installed Tailwind major version before writing config — v4 configures through
    `@tailwindcss/postcss` and a CSS-first `@import "tailwindcss"`, with no `tailwind.config.js`,
    whereas v3 needs the JS config file and the three `@tailwind` directives. Write whichever the
    installed version actually requires; do not assume.

    Create:
    - `tsconfig.json` — `strict: true`, `moduleResolution: "bundler"`, the `next` plugin, path
      alias `@/*` → repo root, and the standard Next.js include/exclude. Ensure `.next` and
      `node_modules` are excluded.
    - `next.config.ts` — minimal typed config; no experimental flags.
    - `postcss.config.mjs` — Tailwind's PostCSS plugin.
    - `app/layout.tsx` — root layout with `<html lang="en">`, metadata title/description drawn
      from the project (Gaspense — vehicle expense tracking), and `globals.css` imported.
      Set the viewport meta appropriately for a mobile-first app.
    - `app/page.tsx` — a deliberately minimal placeholder. Do NOT build dashboard UI, car lists,
      or forms; those belong to later plans. One heading and a line of text is correct here.
    - `app/globals.css` — Tailwind entry point only.

    Add scripts: `"dev": "next dev"` and `"build": "next build"`. Leave every existing script
    untouched.

    Note `package.json` already sets `"type": "module"`, so config files must use ESM syntax.

    Avoid: adding shadcn/ui, component libraries, fonts, or any feature UI. This plan proves the
    app compiles and serves; it does not start the interface.
  </action>
  <verify>npm run build 2>&1 | tail -20 && test -f app/page.tsx && test -f app/layout.tsx && node -e "const p=require('./package.json'); for (const s of ['dev','build','prepare','lint','lint:md','format','format:check','check']) if(!p.scripts?.[s]) throw new Error('missing/lost script: '+s); if(!p.dependencies?.next) throw new Error('next not a runtime dep'); console.log('scripts + deps OK')"</verify>
  <done>AC-1 satisfied: `npm run build` succeeds and the App Router entry points exist</done>
</task>

<task type="auto">
  <name>Task 2: Merge eslint-config-next into the flat config without breaking the gate</name>
  <files>eslint.config.mjs, package.json</files>
  <action>
    Install `eslint-config-next` as a devDependency, then integrate it into the existing
    `tseslint.config(...)` array in `eslint.config.mjs`.

    Determine the correct integration shape from the installed package rather than assuming:
    inspect its exports (`node -e "import('eslint-config-next').then(m=>console.log(Object.keys(m)))"`
    or read its `package.json` exports map). Recent versions ship a flat-config entry point;
    older ones need `FlatCompat` from `@eslint/eslintrc`. Use whichever the installed version
    actually provides — guessing the import shape is the most likely failure here.

    Constraints on the merged config:
    - Next.js rules must apply to `app/**` and any future `src/**`
    - `eslint-config-prettier` must remain the **last** entry so Prettier keeps owning formatting
    - The existing ignore list must be preserved intact: `node_modules`, `.next`, `out`, `build`,
      `dist`, `coverage`, `.paul`, `projects`
    - The typescript-eslint block must keep applying to `**/*.{ts,tsx}`

    Prove the Next.js rules are actually live rather than silently inert: create a temporary file
    that violates a Next-specific rule (for example using `<img>` where `@next/next/no-img-element`
    applies), confirm ESLint reports that specific rule, then delete the file. An `eslint .` that
    exits 0 while loading no Next rules would be a false pass.

    Then run `npm run format` so any generated files satisfy Prettier, and confirm `npm run check`
    is green end to end.

    Avoid: disabling Next.js rules to make the gate pass. If a rule fires on the scaffold, fix the
    code.
  </action>
  <verify>npx eslint . && npm run check && node -e "const p=require('./package.json'); if(!p.devDependencies?.['eslint-config-next']) throw new Error('eslint-config-next missing'); console.log('ok')" && grep -q "prettier" eslint.config.mjs && tail -5 eslint.config.mjs</verify>
  <done>AC-2 satisfied: check gate green with Next.js rules demonstrably active and Prettier still last</done>
</task>

<task type="auto">
  <name>Task 3: Add the build step to CI and verify it green, then confirm nothing was clobbered</name>
  <files>.github/workflows/ci.yml</files>
  <action>
