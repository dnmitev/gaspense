<objective>
## Goal

Complete the test infrastructure Phase 1 deferred: Vitest for unit/integration, Playwright for
end-to-end against the production build, both running in CI — and correct the agent docs, which
currently tell readers that `npm run dev` and `npm run build` do not exist when they do.

## Purpose

This plan closes the last of Phase 1's carried debt and makes the project's stated testing
requirement ("every phase ships unit + integration + automation tests") actually enforceable. Until
`npm test` exists, that requirement is aspirational and PROJECT.md's CI metric stays partially
achieved.

The doc correction is listed first because it is a live inaccuracy: an agent reading `CLAUDE.md`
today will refuse to run commands that work.

## Output

- Vitest + React Testing Library, with a test that genuinely exercises the app
- Playwright e2e against `next start`, including a mobile viewport
- `start`, `test`, `test:e2e` scripts
- `test` and `test:e2e` steps in `.github/workflows/ci.yml`
- Corrected command tables in both agent docs
</objective>

```gherkin
Given the Vitest setup
When `npm test` runs
```

<task type="auto">
  <name>Task 1: Set up Vitest with a non-vacuous unit test</name>
  <files>package.json, vitest.config.ts, tests/unit/page.test.tsx, eslint.config.mjs</files>
  <action>
    Install as devDependencies: `vitest`, `@vitejs/plugin-react`, `jsdom`,
    `@testing-library/react`, `@testing-library/dom`, `@testing-library/jest-dom`.

    Check the installed Vitest major version before writing config — the `environment`/`setupFiles`
    keys and the `globals` default have moved between majors. Read what the installed version
    expects rather than assuming.

    Create `vitest.config.ts`:
    - React plugin, `environment: "jsdom"`, and a setup file importing `@testing-library/jest-dom`
    - Restrict `include` to `tests/unit/**` so Playwright's specs are never picked up by Vitest —
      the two runners must not collide
    - Resolve the `@/*` path alias to match `tsconfig.json`, or imports will fail

    Create `tests/unit/page.test.tsx` — render the actual `app/page.tsx` component and assert on
    real rendered output (the heading text). This is deliberately a smoke test of the whole chain
    (React 19 + TS + jsdom + Tailwind classnames present), because there is barely any application
    logic to test yet. Do not write assertions that would pass against an empty render.

    Add the `test` script. Use a non-watch invocation (`vitest run`) — a watching default would hang
    CI forever.

    Update `eslint.config.mjs` so test files lint cleanly: add `tests/**` awareness if the existing
    config's rules complain (for example about devDependency imports). Do not blanket-ignore
    `tests/**` from linting — test code is code.

    **Prove the runner can fail:** temporarily break an assertion, confirm `npm test` exits
    non-zero and names it, then restore. Read the exit code directly — never through a pipe.
  </action>
  <verify>npm test 2>&1 | tail -15 && node -e "const s=require('./package.json').scripts; if(!s.test) throw new Error('no test script'); if(/--watch|^vitest$/.test(s.test)) throw new Error('test script would watch and hang CI'); console.log('test script ok:', s.test)"</verify>
  <done>AC-1 satisfied: unit suite passes, and was demonstrated failing on a broken assertion</done>
</task>

<task type="auto">
  <name>Task 2: Set up Playwright against the production build, keeping the tree clean</name>
  <files>package.json, playwright.config.ts, tests/e2e/home.spec.ts</files>
  <action>
    Install `@playwright/test` as a devDependency and install the Chromium browser locally.

    Add a `start` script (`next start`) — it does not exist yet and Playwright's `webServer` needs
    it.

    Create `playwright.config.ts`:
    - `testDir: "tests/e2e"`
    - `webServer` running **`npm run build && npm start`** with `reuseExistingServer: !process.env.CI`
      — **not** `npm run dev`. 02-01 established that `next dev` regenerates the
      `nextjs-agent-rules` block in `AGENTS.md`; serving the dev server from the test suite would
      dirty the working tree on every run. Planning verified `next build` does not have this side
      effect.
    - `baseURL` pointing at the served port, with a generous `webServer.timeout` since a production
      build runs first
    - Two projects: a desktop Chromium viewport and a mobile viewport (use a Playwright device
      descriptor). Mobile-first is a stated project convention, so the mobile case is not optional.
    - `forbidOnly: !!process.env.CI` and `retries` only in CI

    Create `tests/e2e/home.spec.ts` — load `/`, assert the visible heading and the document title.
    Keep it to what genuinely exists; there is no navigation, auth, or data yet.

    Add the `test:e2e` script.

    **Prove it can fail** (assert wrong text, confirm non-zero exit, restore), then **prove AC-3**:
    run the full suite and confirm `git status --short` is empty and `AGENTS.md` is unmodified.
  </action>
  <verify>npm run test:e2e 2>&1 | tail -15; echo "e2e exit: $?"; git diff --quiet AGENTS.md && echo "AGENTS.md unmodified" || echo "AGENTS.md DIRTIED"; test -z "$(git status --porcelain)" && echo "tree clean after e2e" || { echo "tree dirty:"; git status --short; }</verify>
  <done>AC-2 and AC-3 satisfied: e2e passes on desktop and mobile viewports, was shown failing, and leaves the tree clean</done>
</task>

<task type="auto">
  <name>Task 3: Add test steps to CI and correct the agent docs</name>
  <files>.github/workflows/ci.yml, CLAUDE.md, AGENTS.md</files>
  <action>
    **CI.** Add to the existing job in `.github/workflows/ci.yml`, after the `Build` step:
    - A `Unit tests` step running `npm test`
    - A Playwright browser install step (`npx playwright install --with-deps chromium`) — CI runners
      do not have browsers preinstalled, and omitting this is the usual first failure
    - An `E2E tests` step running `npm run test:e2e`

    Note the e2e step re-builds via `webServer`, duplicating the `Build` step's work. Accept the
    duplication for now rather than restructuring the workflow — 01-01's triggers, `permissions`,
    and `concurrency` are verified and out of scope here. If the run becomes slow, that is a
    separate optimisation.

    Do not weaken `permissions`, change triggers, or remove `concurrency`.

    **Docs.** Correct the command tables in **both** `CLAUDE.md` and `AGENTS.md`, in this same
    commit — they must never diverge:
    - Every script now exists: `check`, `dev`, `build`, `start`, `lint`, `lint:md`, `format`,
      `format:check`, `test`, `test:e2e`. **Delete the "Not available yet" table entirely** — after
      this plan nothing in it is true.
    - Remove the sentence claiming there is deliberately no `test` script; that is now false.
    - Update the CI/Quality Gates section: CI runs check, build, unit tests, and e2e.
    - Add a short note that e2e serves the production build deliberately, because `next dev`
      rewrites `AGENTS.md`.
    - Keep the "only lint/format tooling installed, no runtime dependencies" claim accurate —
      Next and React are runtime dependencies now, so that line needs correcting too.

    **Do not edit inside AGENTS.md's `<!-- BEGIN:nextjs-agent-rules -->` / `<!-- END -->` markers.**
    Next regenerates that block; edits there are silently lost.

    Then run `npm run format`, confirm `npm run check` is green, commit, push, and watch the CI run
    to completion — a green local suite is not evidence that CI is green.
  </action>
  <verify>grep -q "npm test" .github/workflows/ci.yml && grep -q "playwright install" .github/workflows/ci.yml && grep -q "test:e2e" .github/workflows/ci.yml && ! grep -q "Not available yet" CLAUDE.md && ! grep -q "Not available yet" AGENTS.md && diff <(awk '/^## CI and Quality Gates/{f=1;next} /^## /{f=0} f' CLAUDE.md) <(awk '/^## CI and Quality Gates/{f=1;next} /^## /{f=0} f' AGENTS.md) && npm run check && echo "docs corrected and gate green"</verify>
  <done>AC-4 and AC-5 satisfied: CI runs the full gate green, and neither agent doc misstates what exists</done>
