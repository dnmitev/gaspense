<objective>
## Goal

Establish the lint/format toolchain and a single CI-callable `check` command that verifies the agent docs exist and that all tracked prose passes formatting and lint gates — so Phase 1's GitHub Actions workflow has something concrete to run, and so the first application code written in Phase 2 conforms to style rules that already exist.

## Purpose

Completes Phase 0. Plan 00-01 delivered the documentation half; this delivers the enforcement half. Phase 0's stated testable criterion is a check that fails when `CLAUDE.md` / `AGENTS.md` / `docs/ARCHITECTURE.md` are missing and that runs markdownlint plus the ESLint/Prettier config — that check is the primary output here.

## Output

- `package.json` + `package-lock.json` — npm project with lint/format devDependencies only, no runtime deps
- `eslint.config.mjs` — flat config on a typescript-eslint base, ready to extend with `eslint-config-next` in Phase 2
- `.prettierrc.json`, `.prettierignore` — formatter of record
- `.editorconfig` — editor-level whitespace consistency
- `.markdownlint-cli2.jsonc` — markdown structural rules
- `scripts/check-docs.sh` — docs-presence gate
- `npm run check` — the aggregate command Phase 1's CI invokes
</objective>

<task type="auto">
  <name>Task 1: Bootstrap npm project with lint/format devDependencies</name>
  <files>package.json, package-lock.json</files>
  <action>
    Initialize an npm project (`npm init -y`, then edit) and install lint/format tooling as
    devDependencies only. Use npm — it is the chosen package manager (already installed,
    Vercel's default, simplest CI caching).

    Install as devDependencies:
    - eslint, @eslint/js, typescript-eslint, typescript  (TS-ready lint base)
    - prettier                                           (formatter of record)
    - eslint-config-prettier                             (stops ESLint fighting Prettier)
    - markdownlint-cli2                                   (markdown structural rules)

    Set package.json fields:
    - "name": "gaspense", "private": true, "version": "0.1.0"
    - "type": "module" so eslint.config.mjs and future tooling behave predictably
    - "engines": { "node": ">=20" } — CI and Vercel should agree on a floor

    Add scripts:
    - "lint":         eslint .
    - "lint:md":      markdownlint-cli2
    - "format":       prettier --write .
    - "format:check": prettier --check .
    - "check":        the aggregate — see Task 3. Wire it as
                      `bash scripts/check-docs.sh && npm run format:check && npm run lint && npm run lint:md`

    Do NOT add:
    - Any runtime "dependencies" — Next.js, React, Supabase all arrive in Phase 2
    - A "test" script. There is no test framework and no code to test yet. A no-op passing
      `test` script would give Phase 1's CI a false green, which is worse than an absent script.
      Phase 2 adds the real one.

    Avoid: `npm init` defaults leaving "main": "index.js" pointing at a nonexistent file.
  </action>
  <verify>test -f package.json && test -f package-lock.json && node -e "const p=require('./package.json'); const d=p.dependencies||{}; if(Object.keys(d).length) throw new Error('runtime deps present: '+Object.keys(d)); for(const s of ['lint','lint:md','format','format:check','check']) if(!p.scripts?.[s]) throw new Error('missing script: '+s); if(p.scripts.test) throw new Error('unexpected test script'); console.log('package.json OK')"</verify>
  <done>AC-1 satisfied: devDependencies-only npm project with the five required scripts and no test placeholder</done>
</task>

<task type="auto">
  <name>Task 2: Write ESLint, Prettier, EditorConfig, and markdownlint configs</name>
  <files>eslint.config.mjs, .prettierrc.json, .prettierignore, .editorconfig, .markdownlint-cli2.jsonc</files>
  <action>
    **eslint.config.mjs** — ESLint flat config:
    - Base on @eslint/js recommended + typescript-eslint recommended
    - Apply TS rules to **/*.{ts,tsx}; there are no such files yet, which is expected and must
      not cause failure
    - Append eslint-config-prettier last so formatting rules defer to Prettier
    - Ignore: node_modules, .next, out, build, dist, coverage, .paul, projects
    - Structure it so Phase 2 can append the eslint-config-next flat preset as another array
      entry rather than restructuring

    **.prettierrc.json** — explicit, not defaults-by-omission: singleQuote false, semi true,
    printWidth 100, trailingComma "all", endOfLine "lf".

    **.prettierignore** — must exclude `.paul/`, `projects/`, node_modules, lockfile, and build
    output. Prettier reformatting `.paul/**` would fight PAUL's own templates and rewrite
    STATE.md/ROADMAP.md on every run; `projects/gaspense/PLANNING.md` is a boundary-protected
    append-only record.

    **.editorconfig** — root=true; utf-8, lf, final newline, trim trailing whitespace;
    2-space indent for js/ts/json/md/yml; tab indent for Makefiles if ever added.

    **.markdownlint-cli2.jsonc** — structural rules only, with globs limited to
    `README.md`, `CLAUDE.md`, `AGENTS.md`, `docs/**/*.md`, and ignores for `.paul/**`,
    `projects/**`, `node_modules/**`.

    Critical — Prettier and markdownlint must not fight. Prettier is the formatter of record for
    markdown, so disable the markdownlint rules that Prettier owns. At minimum MD013
    (line-length — the docs use wide tables and long prose lines that wrapping would mangle).
    Determine the remaining conflicting rules empirically: run both tools and disable whichever
    markdownlint rules flag output Prettier itself produced. Do not guess a rule list and hope.

    Avoid: enabling markdownlint over `.paul/**` — those files are machine-written by PAUL and
    linting them would create an unwinnable fight with the framework's templates.
  </action>
  <verify>test -f eslint.config.mjs && test -f .prettierrc.json && test -f .prettierignore && test -f .editorconfig && test -f .markdownlint-cli2.jsonc && npx eslint . && echo "eslint ok" && npx prettier --check . && echo "prettier ok" && npx markdownlint-cli2 && echo "markdownlint ok"</verify>
  <done>AC-2 and AC-3 satisfied: all three tools exit 0 on the same content, protected paths excluded</done>
</task>

<task type="auto">
  <name>Task 3: Add the CI-callable docs-presence check and prove it fails correctly</name>
  <files>scripts/check-docs.sh, CLAUDE.md, AGENTS.md, docs/ARCHITECTURE.md, README.md</files>
  <action>
    Write `scripts/check-docs.sh`:
    - `set -euo pipefail`
    - Assert each of CLAUDE.md, AGENTS.md, docs/ARCHITECTURE.md exists
    - On a missing file: print a message naming that specific file and exit non-zero
    - On success: print a short confirmation and exit 0
    - Keep it POSIX-friendly bash with no dependencies — Phase 1's CI runs it directly
    - Make it executable (`chmod +x`)

    Then bring the existing markdown into compliance so `npm run check` passes end to end:
    - Run `npm run format` and `npm run lint:md` and fix what they report
    - Only README.md, CLAUDE.md, AGENTS.md, and docs/ARCHITECTURE.md may be modified
    - These are **formatting-only** edits. Do not change the meaning, restructure sections, or
      drop content. In particular do not weaken the public-repo secret rules or the
      "don't invent Bulgarian API endpoints" instruction while reformatting.
    - If CLAUDE.md or AGENTS.md needs a content-affecting change, apply the equivalent change to
      both — 00-01 established that they must stay factually identical.

    Finally, update the command tables in CLAUDE.md and AGENTS.md: the npm scripts now exist, so
    change their framing from "planned" to real, and list `npm run check` as the gate. Keep
    `npm test` / `npm run test:e2e` marked as still-to-come in Phase 2, because they genuinely
    do not exist yet.

    Avoid: adding a `.markdownlintignore` that silences real violations instead of fixing them.
  </action>
  <verify>chmod +x scripts/check-docs.sh && npm run check && echo "--- now prove it FAILS when a doc is missing ---" && mv CLAUDE.md /tmp/CLAUDE.md.bak && ! bash scripts/check-docs.sh && echo "correctly failed" && mv /tmp/CLAUDE.md.bak CLAUDE.md && npm run check && echo "restored and passing"</verify>
  <done>AC-4 satisfied: npm run check exits 0 when compliant and non-zero naming the missing file when a doc is removed</done>
</task>
