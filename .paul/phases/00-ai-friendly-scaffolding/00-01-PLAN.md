<objective>
## Goal

Create the agent entry-point documentation (`CLAUDE.md`, `AGENTS.md`), a living architecture reference (`docs/ARCHITECTURE.md`), and a `.gitignore` that enforces the public-repo hygiene constraint — so any AI coding agent or human opening this repo has full context without re-deriving it, and no secret or local artifact can be committed by accident.

## Purpose

Phase 0 exists so every later phase inherits context instead of retrofitting it (PROJECT.md key decision #9). This plan delivers the documentation half. The `.gitignore` is folded in because PROJECT.md's public-repo constraint requires `.env*` ignored with only `.env.example` tracked — and the repo currently has no `.gitignore` at all, with `.claude/worktrees/` already sitting untracked.

## Output

- `CLAUDE.md` — Claude Code project instructions
- `AGENTS.md` — same core context in the cross-tool agents.md standard
- `docs/ARCHITECTURE.md` — data model, API surface, phase roadmap
- `.gitignore` — secrets, dependencies, build output, local tooling artifacts
</objective>

  <name>Task 3: Add .gitignore enforcing public-repo hygiene</name>
  <files>.gitignore</files>
  <action>
    Create .gitignore at the repo root covering:
    - Secrets: .env, .env.local, .env.*.local, and any .env* variant — but explicitly NEGATE
      .env.example (`!.env.example`) so the template stays trackable
    - Node/Next.js: node_modules/, .next/, out/, build/, dist/, *.tsbuildinfo, .turbo/
    - Test/coverage output: coverage/, .nyc_output/, playwright-report/, test-results/

    Order matters: the .env* ignore rule must come BEFORE the !.env.example negation, or the
    negation is dead — git applies last-matching-rule, and a broad later ignore would re-ignore it.

    Do NOT ignore .claude/settings.json — it is intentionally tracked (it carries the repo's
    bgIsolation setting and was committed deliberately).

    Avoid: ignoring .paul/ or projects/ — those are the tracked project brain and must stay in git.
  </action>
